
# 0.5.13 (2026-11-24)

We're happy to announce the release of Scala Native 0.5.13, which ???


## Breaking changes

- **Continuations are now one-shot by default** ([#5259](https://github.com/scala-native/scala-native/pull/5259)). `Continuations.boundary`/`suspend` now run every boundary on its own stack instead of copying it, so frames never move and a continuation can be resumed only once. Code that resumes a continuation more than once must switch to `Continuations.multi`, which keeps the previous stack-copying implementation. 
- **Collection iterators are fail-fast** ([#5310](https://github.com/scala-native/scala-native/pull/5310), [#5312](https://github.com/scala-native/scala-native/pull/5312), [#5314](https://github.com/scala-native/scala-native/pull/5314)). Modifying an `ArrayList`, `Vector`, `LinkedList`, hash-based map/set or `TreeMap`/`TreeSet` while iterating over it now throws `ConcurrentModificationException`, matching the JVM.
- **`ProcessBuilder` no longer falls back to `sh -c`** ([#5245](https://github.com/scala-native/scala-native/pull/5245)). A program not found on `PATH` now throws `IOException` like on the JVM, instead of running the arguments joined into a shell command string.
- **Linking fails for unresolvable virtual calls** ([#5371](https://github.com/scala-native/scala-native/pull/5371)). A virtual call whose allocated receiver class cannot respond to it is now reported as a missing method instead of being dispatched to the only subclass that implements it, e.g. when a subclass overrides a JDK method that javalib does not provide.

## Highlights of the release

### New target platforms

Scala Native can now target and is tested on:

- Windows on ARM64 ([#4936](https://github.com/scala-native/scala-native/pull/4936))
- FreeBSD, OpenBSD and NetBSD ([#5123](https://github.com/scala-native/scala-native/pull/5123))
- Android, via Termux ([#5122](https://github.com/scala-native/scala-native/pull/5122))
- iOS, tvOS and watchOS, tested in the iOS simulator ([#5278](https://github.com/scala-native/scala-native/pull/5278))
- 32-bit ARM v6 and v7a ([#5208](https://github.com/scala-native/scala-native/pull/5208))

Support for musl-based Linux distributions such as Alpine was improved ([#4934](https://github.com/scala-native/scala-native/pull/4934)), and cross compilation to riscv64 is now tested in CI ([#5040](https://github.com/scala-native/scala-native/pull/5040)).

### Calling Scala Native from foreign threads ([#5115](https://github.com/scala-native/scala-native/pull/5115))

Exported methods and function pointer callbacks can now be invoked from threads created outside of Scala Native, for example by a host application or another language runtime. Such threads are attached to the runtime automatically on entry, integrate with all garbage collectors and are cleaned up on exit. The GC deregisters threads ending with `pthread_exit` ([#5173](https://github.com/scala-native/scala-native/pull/5173)) and scans an external thread's stack only within the range it registered and only while it runs Scala code ([#5320](https://github.com/scala-native/scala-native/pull/5320), [#5378](https://github.com/scala-native/scala-native/pull/5378)). This makes embedding Scala Native libraries in other applications practical.

See [Embedding Scala Native](../../user/embedding.md) for initialization of shared libraries, single-threaded builds, exceptions and keeping Scala objects alive in native memory.

### Garbage collectors

- Soft and phantom references are supported in Immix and Commix ([#5368](https://github.com/scala-native/scala-native/pull/5368)).
- Running out of heap now throws `OutOfMemoryError` instead of aborting the program ([#5027](https://github.com/scala-native/scala-native/pull/5027), [#5170](https://github.com/scala-native/scala-native/pull/5170), [#5253](https://github.com/scala-native/scala-native/pull/5253)).
- GC defaults, such as the initial and maximum heap size, GC threads, heap growth ratios or log level, can now be set at build time with `GarbageCollectorConfig` ([#5277](https://github.com/scala-native/scala-native/pull/5277)). They are compiled into the binary, so the program no longer depends on environment variables being set when it starts; the environment variables, e.g. `GC_MAXIMUM_HEAP_SIZE`, still override them at runtime. Settings not supported by the selected collector, or invalid values, fail the build. See [Runtime / Garbage Collector Settings](../../user/runtime.md) for the full list of settings.

  ```scala
  import scala.scalanative.build.*

  nativeConfig ~= {
    _.withGC(GC.immix)
      .withGarbageCollectorConfig(
        _.withInitialHeapSize(64.mb)
          .withMaxHeapSize(2.gb)
      )
  }
  ```
- Cheaper safepoints: all threads poll a single global yieldpoint trap page ([#5243](https://github.com/scala-native/scala-native/pull/5243)), and safepoints are polled on function entry so that tail calls are preserved ([#5283](https://github.com/scala-native/scala-native/pull/5283)).
- Around 30 stability fixes in Immix and Commix, covering deadlocks, mutator starvation, heap growth, interior pointers and roots held in callee-saved registers.

### Concurrency

- `java.lang.invoke.VarHandle` ([#5093](https://github.com/scala-native/scala-native/pull/5093)) and `java.util.concurrent.atomic.Atomic*FieldUpdater` ([#5037](https://github.com/scala-native/scala-native/pull/5037)), both with compiler plugin support
- `java.lang.ClassValue`, now also used to cache `ClassTag`s ([#5192](https://github.com/scala-native/scala-native/pull/5192))
- `ConcurrentSkipList{Map,Set}` ([#5072](https://github.com/scala-native/scala-native/pull/5072)) and `CopyOnWriteArray{List,Set}` ([#5074](https://github.com/scala-native/scala-native/pull/5074)), ported from JSR 166
- Fixes in `ForkJoinPool`, `StampedLock`, `SubmissionPublisher` and `TransferQueue`
- Experimental virtual threads are more stable: fixes to park/unpark, contended monitors and virtual threads blocking inside native callbacks ([#5130](https://github.com/scala-native/scala-native/pull/5130), [#5129](https://github.com/scala-native/scala-native/pull/5129), [#5142](https://github.com/scala-native/scala-native/pull/5142), [#5152](https://github.com/scala-native/scala-native/pull/5152), [#5202](https://github.com/scala-native/scala-native/pull/5202))

### Faster and more predictable builds

- NIR and LLVM IR output is deterministic ([#5141](https://github.com/scala-native/scala-native/pull/5141)).
- Native libraries are no longer recompiled on every build ([#5176](https://github.com/scala-native/scala-native/pull/5176)).
- Incremental cleanup of NIR products works correctly in sbt ([#5096](https://github.com/scala-native/scala-native/pull/5096)).
- Linking NIR from an incompatible Scala Native version now explains the mismatch ([#5118](https://github.com/scala-native/scala-native/pull/5118)).
- LTO builds use Scala Native's own exception handling by default ([#5189](https://github.com/scala-native/scala-native/pull/5189)).
